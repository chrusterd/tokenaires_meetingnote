# 회의록 자동화 — 텍스트 경로 MVP 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 회의 메모를 붙여넣으면 → LLM이 구조화 → 사람이 화면에서 검토·수정 → Notion 회의록 DB + 액션아이템 DB에 저장되는, Netlify에 배포 가능한 웹앱을 만든다.

**Architecture:** React(Vite) SPA + Netlify Functions. 브라우저는 API 키를 절대 보지 않는다 — Groq·Notion 호출은 전부 서버리스 함수 안에서만 일어난다. 모든 모듈은 `MeetingRecord`라는 단일 JSON 계약을 주고받는다. Notion 스키마를 가장 먼저 고정하고, 그 다음에 그 스키마를 채우는 구조화 모듈을 만든다(기획서 v2 §7의 근거를 그대로 따름).

**Tech Stack:** React 18 + TypeScript + Vite / Netlify Functions v2 (Node) / Vitest / Groq API (`llama-3.3-70b-versatile`) / Notion API (`2022-06-28`)

> **셸 주의:** 명령 블록은 한 줄에 하나씩 실행하도록 나눠 두었다. PowerShell 5.1에는 `&&`가 없어 파서 오류가 난다.
> `curl` 명령은 **Git Bash에서 실행한다** — PowerShell의 `curl`은 `Invoke-WebRequest` 별칭이라 `-X`, `-d`, `-H` 플래그를 그대로 못 받는다.

## 이 계획의 범위

**포함:** 텍스트 붙여넣기 → 구조화 → 검토 → Notion 저장 → 액션아이템 대시보드
(작업계획 §통합순서의 "1차 통합", 기획서 v2 §7의 3→4→2 경로)

**제외 — 오디오 경로 (Phase 2로 연기, 사용자 확정):**
Netlify의 측정된 제약 때문에 오디오를 지금 구조에 그대로 얹을 수 없다.

| 항목 | 값 |
|------|-----|
| 동기 함수 실행 시간 | 60초 |
| 동기 함수 요청/응답 본문 | 6MB (바이너리는 base64 인코딩으로 실질 **~4.5MB**) |
| 백그라운드 함수 | 15분, 요청/응답 **256KB**, 클라이언트에는 `202`만 반환 |
| Groq 전사 업로드 한도 | 25MB (무료) / 100MB (유료) |

60분 회의 녹음은 4.5MB를 훨씬 넘으므로 **오디오 바이트가 동기 함수를 통과할 수 없다.**

Phase 2의 형태만 기록해 둔다: 브라우저가 오디오를 blob 스토리지에 직접 업로드하고 → 백그라운드 함수가 그 키를 읽어 Groq `whisper-large-v3-turbo`(`https://api.groq.com/openai/v1/audio/transcriptions`)를 호출한 뒤 전사문을 다시 스토리지에 쓰고 → 클라이언트는 상태 조회 엔드포인트를 폴링한다. 동기 함수는 오디오 바이트를 절대 만지지 않는다. **이 계획에서는 구현하지 않는다.**

## Global Constraints

모든 태스크의 요구사항에 아래가 암묵적으로 포함된다.

- **`VITE_` 접두사를 가진 환경변수에 비밀키를 절대 넣지 않는다.** Vite는 `VITE_*`를 클라이언트 번들에 그대로 인라인한다 — `VITE_GROQ_API_KEY`는 방문자 전원에게 키를 배포하는 것이다. 모든 키는 Netlify Functions 환경변수로만 존재한다. (Netlify 빌드 시 시크릿 스캐너에도 걸린다.)
- **JSON 계약의 키 이름은 한국어 그대로 사용한다** — `날짜`, `참석자`, `안건_태그`, `핵심_요약`, `결정사항`, `액션아이템`, `논의_요약`, `전사문`. TypeScript 타입, LLM 프롬프트, 네트워크 페이로드 전부 동일해야 한다. 영어로 흘러가기 쉬우니 주의.
- **Notion API 버전은 `2022-06-28`로 고정한다.** 상수 하나(`NOTION_VERSION`)로만 정의하고 모든 요청 헤더에서 그 상수를 쓴다. (2025-09-03부터 database/data source 개념이 분리되므로 옛 예제와 섞이면 깨진다. 2022-06-28은 `database_id`를 직접 쓰는 안정 버전.)
- **Notion 레이트 리밋 초당 3요청.** 액션아이템을 반복 생성할 때 요청 사이에 최소 350ms 지연을 넣는다.
- **JSON 파싱 실패 시 재시도는 최대 2회.** 그 후에는 원본 텍스트를 그대로 검토 화면에 넘겨 사람이 처리하게 한다. 무한 재시도 금지.
- **담당자·기한을 추론하지 않는다.** 명시되지 않으면 문자열 `"미정"`.
- Node 20 이상.

- [ ] **Step 4: 최소 구현 작성**

`shared/contract.ts`:

```ts
export interface ActionItem {
  할일: string
  담당자: string   // 미상이면 "미정"
  기한: string     // "YYYY-MM-DD" 또는 "미정"
}

export interface MeetingRecord {
  날짜: string     // "YYYY-MM-DD"
  참석자: string[]
  안건_태그: string[]
  핵심_요약: string
  결정사항: string[]
  액션아이템: ActionItem[]
  논의_요약: string[]
  전사문: string
}

export const UNSET = '미정'

export const EMPTY_RECORD: MeetingRecord = {
  날짜: new Date().toISOString().slice(0, 10),
  참석자: [],
  안건_태그: [],
  핵심_요약: '',
  결정사항: [],
  액션아이템: [],
  논의_요약: [],
  전사문: '',
}

const DATE_RE = /^\d{4}-\d{2}-\d{2}$/

type ValidationResult =
  | { ok: true; value: MeetingRecord }
  | { ok: false; errors: string[] }

export function validateMeetingRecord(value: unknown): ValidationResult {
  const errors: string[] = []
  if (typeof value !== 'object' || value === null) {
    return { ok: false, errors: ['최상위 값이 객체가 아닙니다'] }
  }
  const raw = value as Record<string, unknown>

  const stringArray = (key: keyof MeetingRecord): string[] => {
    const v = raw[key]
    if (v === undefined) { errors.push(`${key} 누락`); return [] }
    if (!Array.isArray(v)) { errors.push(`${key}는 배열이어야 합니다`); return [] }
    return v.map(String)
  }

  const 날짜 = typeof raw.날짜 === 'string' ? raw.날짜 : ''
  if (!날짜) errors.push('날짜 누락')
  else if (!DATE_RE.test(날짜)) errors.push('날짜는 YYYY-MM-DD 형식이어야 합니다')

  const 참석자 = stringArray('참석자')
  const 안건_태그 = stringArray('안건_태그')
  const 결정사항 = stringArray('결정사항')
  const 논의_요약 = stringArray('논의_요약')

  if (typeof raw.핵심_요약 !== 'string') errors.push('핵심_요약 누락')
  if (typeof raw.전사문 !== 'string') errors.push('전사문 누락')

  let 액션아이템: ActionItem[] = []
  if (!Array.isArray(raw.액션아이템)) {
    errors.push('액션아이템 누락')
  } else {
    액션아이템 = raw.액션아이템.map((item) => {
      const o = (item ?? {}) as Record<string, unknown>
      const 기한 = typeof o.기한 === 'string' ? o.기한.trim() : ''
      return {
        할일: typeof o.할일 === 'string' ? o.할일 : '',
        담당자: typeof o.담당자 === 'string' && o.담당자.trim() ? o.담당자.trim() : UNSET,
        기한: 기한 && DATE_RE.test(기한) ? 기한 : UNSET,
      }
    })
  }

  if (errors.length) return { ok: false, errors }

  return {
    ok: true,
    value: {
      날짜,
      참석자,
      안건_태그,
      핵심_요약: raw.핵심_요약 as string,
      결정사항,
      액션아이템,
      논의_요약,
      전사문: raw.전사문 as string,
    },
  }
}

import type { MeetingRecord, ActionItem } from '../../../shared/contract'
import { UNSET } from '../../../shared/contract'

const RICH_TEXT_LIMIT = 2000
const MAX_CHILDREN = 100

type RichText = { type: 'text'; text: { content: string } }

export function splitRichText(text: string): RichText[] {
  if (!text) return [{ type: 'text', text: { content: '' } }]
  const chunks: RichText[] = []
  for (let i = 0; i < text.length; i += RICH_TEXT_LIMIT) {
    chunks.push({ type: 'text', text: { content: text.slice(i, i + RICH_TEXT_LIMIT) } })
  }
  return chunks
}

const heading = (text: string) => ({
  object: 'block', type: 'heading_2',
  heading_2: { rich_text: [{ type: 'text', text: { content: text } }] },
})

const bullet = (text: string) => ({
  object: 'block', type: 'bulleted_list_item',
  bulleted_list_item: { rich_text: splitRichText(text) },
})

const paragraph = (text: string) => ({
  object: 'block', type: 'paragraph',
  paragraph: { rich_text: splitRichText(text) },
})

export function buildMeetingPage(record: MeetingRecord, databaseId: string) {
  // 전사문은 문단당 2000자씩 쪼개고, 토글의 자식으로 넣는다.
  const 전사문_문단 = record.전사문
    ? record.전사문.match(/[\s\S]{1,2000}/g)!.map(paragraph)
    : [paragraph('(전사문 없음)')]

  const children: object[] = [
    paragraph('이 회의록은 자동 생성 후 사람이 검토·승인한 기록입니다.'),
    heading('결정사항'),
    ...record.결정사항.map(bullet),
    heading('논의 내용 요약'),
    ...record.논의_요약.map(bullet),
    {
      object: 'block', type: 'toggle',
      toggle: {
        rich_text: [{ type: 'text', text: { content: '전사 전문' } }],
        children: 전사문_문단.slice(0, MAX_CHILDREN),
      },
    },
  ]

  return {
    parent: { database_id: databaseId },
    properties: {
      // '진행 상태'는 rollup이라 쓰기 불가 — 넣지 않는다.
      '제목': { title: [{ type: 'text', text: { content: `${record.날짜} 회의록` } }] },
      '날짜': { date: { start: record.날짜 } },
      '참석자': { multi_select: record.참석자.map((name) => ({ name })) },
      '안건 태그': { multi_select: record.안건_태그.map((name) => ({ name })) },
      '핵심 요약': { rich_text: splitRichText(record.핵심_요약) },
    },
    children: children.slice(0, MAX_CHILDREN),
  }
}

export function buildActionItemPage(item: ActionItem, databaseId: string, meetingPageId: string) {
  return {
    parent: { database_id: databaseId },
    properties: {
      '할 일': { title: [{ type: 'text', text: { content: item.할일 } }] },
      '담당자': { multi_select: [{ name: item.담당자 || UNSET }] },
      '기한': { date: item.기한 && item.기한 !== UNSET ? { start: item.기한 } : null },
      '완료': { checkbox: false },
      '회의': { relation: [{ id: meetingPageId }] },
      '출처': { select: { name: 'AI추출' } },
    },
  }
}

import type { MeetingRecord, ActionItem } from '../../../shared/contract'
import { buildMeetingPage, buildActionItemPage } from './notion-mapping'

export const NOTION_VERSION = '2022-06-28'
const BASE = 'https://api.notion.com/v1'

// 레이트 리밋 초당 3요청 → 요청 사이 최소 350ms
const RATE_LIMIT_DELAY_MS = 350
const sleep = (ms: number) => new Promise((r) => setTimeout(r, ms))

export async function notionFetch(path: string, init: RequestInit = {}) {
  const res = await fetch(`${BASE}${path}`, {
    ...init,
    headers: {
      'Authorization': `Bearer ${process.env.NOTION_TOKEN}`,
      'Notion-Version': NOTION_VERSION,
      'Content-Type': 'application/json',
      ...(init.headers ?? {}),
    },
  })
  const body = await res.json()
  if (!res.ok) {
    throw new Error(`Notion ${res.status}: ${body.message ?? JSON.stringify(body)}`)
  }
  return body
}

/**
 * existingPageId를 주면 회의록 페이지를 새로 만들지 않고
 * 그 페이지에 액션아이템만 붙인다 (부분 실패 재시도용).
 * 이게 없으면 재시도가 회의록 페이지를 하나 더 만들어
 * 공식 기록이 둘로 갈라지고 rollup도 쪼개진다.
 */
export async function createMeeting(record: MeetingRecord, existingPageId?: string) {
  const meetingsDb = process.env.NOTION_MEETINGS_DB!
  const actionsDb = process.env.NOTION_ACTIONS_DB!

  const page = existingPageId
    ? { id: existingPageId, url: `https://www.notion.so/${existingPageId.replace(/-/g, '')}` }
    : await notionFetch('/pages', {
        method: 'POST',
        body: JSON.stringify(buildMeetingPage(record, meetingsDb)),
      })

  // 부분 실패를 롤백하지 않는다 — Notion에 트랜잭션이 없다.
  // 실패한 항목만 돌려주고 화면에서 재시도하게 한다.
  const failedItems: ActionItem[] = []
  for (const item of record.액션아이템) {
    await sleep(RATE_LIMIT_DELAY_MS)
    try {
      await notionFetch('/pages', {
        method: 'POST',
        body: JSON.stringify(buildActionItemPage(item, actionsDb, page.id)),
      })
    } catch {
      failedItems.push(item)
    }
  }

  return { pageId: page.id as string, pageUrl: page.url as string, failedItems }
}
```

import type { Config } from '@netlify/functions'
import { validateMeetingRecord } from '../../shared/contract'
import { createMeeting } from './_lib/notion'

export default async (req: Request) => {
  if (req.method !== 'POST') return new Response('Method not allowed', { status: 405 })

  // pageId가 있으면 재시도 — 기존 회의록 페이지에 액션아이템만 붙인다.
  // validateMeetingRecord는 모르는 키를 무시하므로 계약은 그대로다.
  const { pageId, ...body } = await req.json()

  const parsed = validateMeetingRecord(body)
  if (!parsed.ok) {
    return Response.json({ error: '계약 위반', details: parsed.errors }, { status: 400 })
  }

  try {
    const result = await createMeeting(parsed.value, pageId)
    return Response.json({
      pageId: result.pageId,
      pageUrl: result.pageUrl,
      failedItems: result.failedItems,
    })
  } catch (e) {
    return Response.json({ error: (e as Error).message }, { status: 502 })
  }
}

export const config: Config = { path: '/api/notion-create' }

# 전역 지시

# 항목별 규칙

## 핵심_요약
3줄 이내의 한 문자열. 회의 전체를 요약한다.

## 결정사항
확정 표현("~로 결정", "~하기로 함", "~로 가자")이 있는 것만 넣는다.
여러 명이 동의한 내용은 결정으로 본다.
불확실한 것을 결정으로 승격시키지 않는다. 애매하면 논의_요약으로 보낸다.

## 액션아이템
할일 / 담당자 / 기한 세 필드.
담당자가 메모에 명시되지 않았으면 "미정"으로 둔다. 문맥으로 추론하지 않는다.
기한이 언급되지 않았으면 "미정"으로 둔다. 날짜를 추측해서 채우지 않는다.
기한이 있으면 YYYY-MM-DD 형식으로만 쓴다.

## 논의_요약
결론이 나지 않은 것, 보류된 것, 다음 회의로 넘어간 것.
3~5개 항목. "결론이 나지 않았다"는 사실 자체를 문장에 명시한다.

# 출력 형식
아래 JSON만 출력한다. 설명·인사·코드펜스를 붙이지 않는다.

{
  "핵심_요약": "문자열",
  "안건_태그": ["기획" | "개발" | "디자인" | "기타" 중 해당하는 것],
  "결정사항": ["문자열"],
  "액션아이템": [{ "할일": "문자열", "담당자": "문자열 또는 미정", "기한": "YYYY-MM-DD 또는 미정" }],
  "논의_요약": ["문자열"]

export function parseModelResponse(text: string): unknown {
  const trimmed = text.trim()

  // 코드펜스 제거
  const fenced = trimmed.match(/```(?:json)?\s*([\s\S]*?)```/)
  const candidate = fenced ? fenced[1] : trimmed

  try {
    return JSON.parse(candidate)
  } catch {
    // 앞뒤 설명이 붙은 경우 가장 바깥 중괄호 구간만 뽑는다
    const start = candidate.indexOf('{')
    const end = candidate.lastIndexOf('}')
    if (start === -1 || end <= start) {
      throw new Error('응답에서 JSON을 찾지 못했습니다')
    }
    return JSON.parse(candidate.slice(start, end + 1))
  }
}

import type { Config } from '@netlify/functions'
import { validateMeetingRecord, type MeetingRecord } from '../../shared/contract'
import { SYSTEM_PROMPT, parseModelResponse } from './_lib/structure-prompt'

const GROQ_URL = 'https://api.groq.com/openai/v1/chat/completions'
const MODEL = 'llama-3.3-70b-versatile'
const MAX_ATTEMPTS = 3   // 최초 1회 + 재시도 2회

async function callGroq(text: string): Promise<string> {
  const res = await fetch(GROQ_URL, {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${process.env.GROQ_API_KEY}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      model: MODEL,
      temperature: 0.2,
      response_format: { type: 'json_object' },
      messages: [
        { role: 'system', content: SYSTEM_PROMPT },
        { role: 'user', content: text },
      ],
    }),
  })
  const body = await res.json()
  if (!res.ok) throw new Error(`Groq ${res.status}: ${body.error?.message ?? '알 수 없는 오류'}`)
  return body.choices[0].message.content as string
}

export default async (req: Request) => {
  if (req.method !== 'POST') return new Response('Method not allowed', { status: 405 })

  const { 텍스트, 날짜, 참석자 } = await req.json()

  // 입력 검증은 반드시 재시도 루프 밖에서 먼저 한다.
  // 안 그러면 클라이언트 입력 오류 하나에 Groq를 3번 호출한다.
  if (!텍스트?.trim()) {
    return Response.json({ error: '회의 내용이 비어 있습니다' }, { status: 400 })
  }
  if (typeof 날짜 !== 'string' || !/^\d{4}-\d{2}-\d{2}$/.test(날짜)) {
    return Response.json({ error: '날짜는 YYYY-MM-DD 형식이어야 합니다' }, { status: 400 })
  }
  if (참석자 !== undefined && !Array.isArray(참석자)) {
    return Response.json({ error: '참석자는 배열이어야 합니다' }, { status: 400 })
  }

  let lastRaw = ''
  for (let attempt = 1; attempt <= MAX_ATTEMPTS; attempt++) {
    try {
      lastRaw = await callGroq(텍스트)
      const parsed = parseModelResponse(lastRaw) as Record<string, unknown>

      const candidate: MeetingRecord = {
        날짜,
        참석자: 참석자 ?? [],
        안건_태그: (parsed.안건_태그 as string[]) ?? [],
        핵심_요약: (parsed.핵심_요약 as string) ?? '',
        결정사항: (parsed.결정사항 as string[]) ?? [],
        액션아이템: (parsed.액션아이템 as MeetingRecord['액션아이템']) ?? [],
        논의_요약: (parsed.논의_요약 as string[]) ?? [],
        전사문: 텍스트,   // 텍스트 입력은 입력값을 그대로 원본으로 보존
      }

      const validated = validateMeetingRecord(candidate)
      if (validated.ok) return Response.json(validated.value)
      if (attempt === MAX_ATTEMPTS) {
        return Response.json(
          { error: '구조화 결과가 계약을 만족하지 않습니다', details: validated.errors, raw: lastRaw },
          { status: 422 },
        )
      }
    } catch (e) {
      if (attempt === MAX_ATTEMPTS) {
        return Response.json({ error: (e as Error).message, raw: lastRaw }, { status: 502 })
      }
    }
  }
}

`src/App.tsx`를 아래로 교체:

```tsx
import { useState } from 'react'
import type { MeetingRecord, ActionItem } from '../shared/contract'
import { InputScreen } from './components/InputScreen'
import { ReviewScreen } from './components/ReviewScreen'
import { ResultScreen } from './components/ResultScreen'
import { createNotionPage } from './api'

type Screen = 'input' | 'review' | 'result'

export default function App() {
  const [screen, setScreen] = useState<Screen>('input')
  const [record, setRecord] = useState<MeetingRecord | null>(null)
  const [pageId, setPageId] = useState('')
  const [pageUrl, setPageUrl] = useState('')
  const [failedItems, setFailedItems] = useState<ActionItem[]>([])
  const [저장중, set저장중] = useState(false)
  const [오류, set오류] = useState('')

  const 저장 = async (edited: MeetingRecord) => {
    set저장중(true); set오류('')
    try {
      const res = await createNotionPage(edited)
      setRecord(edited); setPageId(res.pageId); setPageUrl(res.pageUrl)
      setFailedItems(res.failedItems)
      setScreen('result')
    } catch (e) {
      set오류((e as Error).message)
    } finally {
      set저장중(false)
    }
  }

  // pageId를 함께 보내 기존 회의록 페이지에 붙인다 — 페이지가 두 개 생기면 안 된다
  const 실패항목_재시도 = async () => {
    if (!record) return
    set오류('')
    try {
      const res = await createNotionPage({ ...record, 액션아이템: failedItems }, pageId)
      setFailedItems(res.failedItems)
    } catch (e) {
      set오류((e as Error).message)
    }
  }

  const 새로작성 = () => {
    setRecord(null); setPageId(''); setPageUrl(''); setFailedItems([]); setScreen('input')
  }

  return (
    <main>
      {오류 && <p role="alert">저장 실패: {오류}</p>}

      {screen === 'input' && (
        <InputScreen onStructured={(r) => { setRecord(r); setScreen('review') }} />
      )}

      {screen === 'review' && record && (
        <>
          {저장중 && <p>노션에 저장하는 중…</p>}
          <ReviewScreen record={record} onBack={() => setScreen('input')} onApprove={저장} />
        </>
      )}

      {screen === 'result' && record && (
        <ResultScreen
          pageUrl={pageUrl}
          record={record}
          failedItems={failedItems}
          onRetryFailed={실패항목_재시도}
          onNew={새로작성}
        />
      )}
    </main>
  )
}
```

재시도는 `pageId`를 함께 보내므로 회의록 페이지를 새로 만들지 않고 기존 페이지에 실패한 액션아이템만 붙인다. 페이지가 둘로 갈라지면 어느 쪽이 공식 기록인지 알 수 없고 `진행 상태` rollup도 쪼개진다.

import { useEffect, useState } from 'react'
import { fetchActionItems, toggleActionItem, type DashboardItem } from '../api'

const 팀원 = ['소정', '하영', '해냄', '유진']

export function ActionDashboard() {
  const [items, setItems] = useState<DashboardItem[]>([])
  const [내담당, set내담당] = useState('')
  const [오류, set오류] = useState('')
  const [로딩, set로딩] = useState(true)

    fetchActionItems()
      .then(setItems)
      .catch((e) => set오류((e as Error).message))
      .finally(() => set로딩(false))
  }, [])

  const 완료처리 = async (id: string) => {
    const 이전 = items
    setItems(items.filter((it) => it.id !== id))   // 낙관적 갱신
    try {
      await toggleActionItem(id, true)
    } catch (e) {
      setItems(이전)
      set오류(`완료 처리 실패: ${(e as Error).message}`)
    }
  }

  const 보이는목록 = 내담당
    ? items.filter((it) => it.담당자.includes(내담당))
    : items

  if (로딩) return <p>불러오는 중…</p>

  return (
    <section>
      <h1>미완료 할 일</h1>
      {오류 && <p role="alert">{오류}</p>}

      <label>담당자
        <select value={내담당} onChange={(e) => set내담당(e.target.value)}>
          <option value="">전체</option>
          {팀원.map((n) => <option key={n} value={n}>{n}</option>)}
        </select>
      </label>

      {보이는목록.length === 0 ? (
        <p>표시할 할 일이 없습니다.</p>
      ) : (
        <ul>
          {보이는목록.map((it) => (
            <li key={it.id}>
              <input type="checkbox" checked={false} onChange={() => 완료처리(it.id)} />
              {it.할일}
              <small> — {it.담당자.join(', ')} · 기한 {it.기한 ?? '미정'}</small>
            </li>
          ))}
        </ul>
      )}
    </section>
  )
}
